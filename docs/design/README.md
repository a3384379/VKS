# 知境 VKS 1.0 设计交付包

本交付包是一套可用于产品评审、技术评审和开发任务拆分的设计基线，**不是已经实现的产品**。编制日期：2026-10-25。

## 从哪里开始

1. 首先阅读 [完整开发设计方案](VKS_1.0_完整开发设计方案.md) 的方案摘要、第 1–4 章，确认 1.0 的目标、范围和功能。
2. 产品与前端开发重点阅读第 5–8 章及 [8 张 UI 图](ui/README.md)。
3. 后端与 AI 集成开发重点阅读第 9–17 章和 [可机读契约](contracts/README.md)。
4. 交付负责人阅读第 18–23 章：质量门禁、部署、排期、风险、任务映射与 35 条验收用例。
5. 第 24 章保留官方仓库和文档来源。开源组件实际采用前需要锁定版本、复核依赖和许可证。

## 阅读方式

- 推荐解压完整 ZIP，保持目录不变后，用支持 Markdown 的编辑器打开主文档。
- Markdown 内的 UI 图片使用相对路径。单独下载主文档时，文字、表格、JSON 与 Mermaid 源码仍完整，但图片需要同目录附件。
- 阅读器支持 Mermaid 时可直接看到图；不支持时，使用每张图后的 PNG/SVG 链接。
- UI 图片采用冰蓝＋白色，固定 1586×992 像素，只表达布局与视觉方向。图片内的数据、API 示例、代码、金额和版本均属合成演示，不代表对实际公司项目的审计结果。
- 图中示例业务基线 v1.22 是被管理项目的版本，不是 VKS 产品版本；VKS 产品设计基线为 1.0。
- 全部文字文件采用 UTF-8，无需全仓转码。后续平台导入已有项目时，必须保留原字节、BOM 和换行，不修改来源仓库。

## 使用边界

- 从“操作”进入“知识”，不等于执行真实业务。默认讲解模式不发出支付、开票、退款、删除等业务请求。
- 外部 AI 可以将原型、Markdown、章节 sidecar 与显式绑定清单一起导入，平台不强制配置内置模型。
- 自动匹配产生候选，不意味着因果和业务语义已经被验证；发布仍有独立审核。
- 技术图依据正式数据结构和流程人工编排，UI 效果图为图像生成概念稿；任何字段冲突以评审冻结后的正文和 contracts 为准。
- 本交付未连接实际公司仓库、未编译或运行原项目、未执行 Maven，也没有修改原项目代码。

建议首次实施先打通“一个页面动作＋一个文档章节＋一个 API＋一份证据”的 Web/MCP 双入口闭环，再扩展分析器与采集适配。
