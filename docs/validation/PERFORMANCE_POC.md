# 读取与静态任务 PoC 结果

2026-10-25，本机 macOS 26.6.2 arm64 / 10 CPU / 16 GiB。正式门禁要求的 8 vCPU/16 GiB、SSD、固定网络基准机以及 PostgreSQL 专项仍需单独验收；Docker 可用约 7.75 GiB，不满足该资源剖面。以下结果不表示正式 AT-34/35 门禁已签署。

## AT-34：真实 HTTP 20 并发 10 分钟

固定合成发布版：50,000 关系、1,000 动作、200 MD。真实 loopback HTTP 包含机器令牌鉴权与响应序列化，动作与图谱默认 depth=2、max_nodes=50；检索 limit=10。共持续 600.496 秒、34,197 请求，错误为 0；被测读取源码在测量期间未变化。

| 读取 | 请求数 | p50 ms | p95 ms | p99 ms |
| --- | ---: | ---: | ---: | ---: |
| 动作知识 | 11,405 | 399.357 | 495.677 | 612.137 |
| 全文/符号检索 | 11,398 | 222.190 | 337.905 | 780.098 |
| 局部图谱 | 11,394 | 402.677 | 497.129 | 601.942 |

首波 20 个冷启动请求 p95=754.246ms；随后 34,177 个热读取请求 p95=486.349ms。每 10 秒的 API 进程资源采样为 RSS 104.7–203.5 MiB、CPU 70.2–97.1%；CPU 百分比采用本机 `ps` 的单进程定义，不能当作整机使用率。没有外部模型时间被扣除，模型调用数为零。

优化前同数据的应用服务方法采样为 20 并发各一次动作读取：p50=26.780s、p95/p99=34.234s，215,240 SQL。此项未包含 HTTP，与最终 HTTP 数据分别保留。完整 workspace 是单独的全量概览，冷启动单请求耗时 1.961s；没有把它混入局部动作/搜索分布，也没有对它声称通过 20 并发门禁。

读取使用独立只读事务、一致快照、事务内授权缓存和批量可见性检查。发布事实缓存仅含不可变版本选择与边，权限与制品策略每次重新检查；关系 DTO 会复制，低权限裁剪不能改变共享事实。局部读取不再加载整个 workspace。SQLite 检索使用 Unicode casefold UDF 后再执行完整匹配；PostgreSQL 保留正确的列投影匹配路径，尚未据本机 SQLite 数据声称 PostgreSQL 性能。

## AT-35：5,000 文件 / 100 MiB 实际导入

合法 Java 简单类与注释填充，实际材料为 5,000 文件、104,857,600 字节。ZIP 连同 manifest 为 5,001 条目、106,383,032 展开字节；传输 61,959,867 字节。该数据规模不能替代企业代码复杂度评估，零调用样本不提供调用准确率结论。
