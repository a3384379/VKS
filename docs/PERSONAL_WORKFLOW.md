# 自用知识工作流（2026-10-31）

本约定按项目维护人的明确要求，替代旧设计中审批、审核队列及内容脱敏部分。`docs/design/` 和 `docs/upgrades/v2/design/` 原件保留；历史实施和验收记录描述当时行为，不作为重新加入审批的要求。

资料导入、文档保存、流程维护和模型任务的产物直接可用。知识关联保留用户移除状态 `excluded`、来源有效性、证据和因果依据；这些字段含义独立。用户可以纠错、移除或恢复关联，来源变化不会复活已经移除的关系，也不会把静态信息升级为运行事实。文档章节锁、逻辑身份、准确修订映射和原始附件继续保留。

“变更与版本”直接保存不可变快照。HTTP `POST /api/v2/projects/{pid}/snapshots` 与 MCP `save_knowledge_snapshot` 共用服务，只需知识编辑权限；无需提交、批准、签署或发布票据。知识任务计划通过结构和范围校验后继续执行，不再等待计划确认；暂停、取消、租约、重试和模型预算仍有效。

浏览器采集直接指定 `analysis_set_id`、`scenario_revision_id`、`environment_ref`。服务器固定环境、数据集和输入版本，执行与提交时校验其一致性，不签发审批票据。页面原始 HTML、截图和普通文本不做内容遮罩；导入、导出和模型输入不再按秘密特征过滤正文。环境和网络配置、项目权限、原始数据不执行、被动 HTML 渲染、路径/ZIP 限制和日志中不输出认证凭据等基础约束继续存在。采集的 Trace 仍按已实现格式记录请求方法、路径、状态与时序，不自动增加请求正文录制功能。

审核中心、项目审核开关、文档审核、关系批量审核、流程审核、变更提案批准、计划确认及采集审批接口均删除。MCP 不再暴露发布预检工具 `request_release`，关系检查提示改名为 `inspect_link_evidence`。知识上下文关系策略统一为 `valid`、`outdated`、`all`；知识地图使用 `valid_only`。

## 迁移与回退

Alembic `j93dca582910` 升级 PostgreSQL；开发 SQLite 在服务初始化前执行同等迁移。删除六类治理表及审批/脱敏字段；旧 rejected 关系转为 `excluded=true`，其余关系直接参与有效知识查询。旧 reviewer 角色迁为 editor，等待审核的可编辑知识和计划恢复到普通工作流。原始制品、证据、修订、选择和已保存快照保留；历史快照 JSON 与摘要不改写，仅在读取边界解释旧关系字段。

升级前需备份数据库与对象目录，并在隔离副本验证恢复。移除的审批历史无法通过降级脚本重新构造，回退使用同一次一致备份及对应旧二进制。历史截图已遮罩的像素无法恢复，重新采集才会得到完整截图。

审批专属测试随功能删除；关系纠错、并发版本、历史读取、数据迁移、权限过滤、采集、文档导航、画布和导出回归改为验证直接使用的行为。源代码及数据的改动前完整备份保存在忽略目录，具体检查结果记录在验证文档。
