# 项目审核策略（2026-10-29）

2026-10-31：本页仅保留历史实现记录。审批模块和此处的项目开关已移除，当前约定见[自用知识工作流](../../PERSONAL_WORKFLOW.md)。

用户要求变更与审核默认自动通过，需要时再开启人工审核。本次实现替代此前“新增知识始终待审”的默认行为；原设计交付件保持不变。

## 使用方式

在 **项目设置 → 项目资料 → 变更与审核设置** 勾选“启用人工审核”并保存。默认不勾选；每个项目独立保存。开启后，新关系、流程、文档和迁移提案等待人工审核；关闭时立即处理当前项目所有未冻结草稿的合格待审内容。重新开启不会撤销已有审批。

没有显式项目设置时默认自动。需要部署级人工审核基线时可设置 `VKS_DEFAULT_MANUAL_REVIEW=1`，显式项目设置优先。已有待审数据的只读查询不会产生审批；保存自动策略或后续知识写入时才处理。

## 实现与权限

- `review_policy.py` 在知识写入事务提交前执行服务器策略。策略以现有不可变 `Audit` 事件保存，无新增表、列或依赖。
- `GET/PUT /api/v2/projects/{pid}/review-policy` 提供读取与保存；保存需要人员会话、`project:manage`、`links:review` 和当前项目行版本 `If-Match`。公共响应只包含项目、模式和行版本，不暴露其他权限范围的数量。
- 自动决定使用独立系统身份及 `decision_origin=automatic_policy` 审计，不冒充人工审核。机器仍只能提交获授权提案，不能调用审批、策略设置或发布端点。Web 和 MCP 使用相同应用服务，返回实际保存的审批状态。
- 合法、有效且未被人员锁定的候选关系可确认；静态证据、有效性与运行因果分别保留。自动确认不生成运行证据。
- 流程校验当前准确引用后，审批绑定修订与摘要。文档审批同时核对当前选择的准确章节映射，绑定新文档修订与摘要；原字节与历史修订不改。
- 迁移提案只确认当前准确修订和目标关系版本。过期提案保持待审；接受迁移不将 `stale/broken` 关系改为有效。人员拒绝、章节锁和冻结发布不被覆盖。
- 自动策略不发布知识、不确认自然语言执行计划、不授权 Runner 业务采集；这些行为保留各自的明确人员确认。
- 任务报告区分 `automatic` / `manual`，自动模式完成阶段为 `COMPLETE`；审核页显示当前项目模式。
