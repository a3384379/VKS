# 资料管理性能与重复导入修复 · 2026-11-14

基线 `eb7026c`。本轮针对资料管理列表、更新、误新增重复资料、删除入口，以及后续反馈的迁移进度、用量限制、助手阅读顺序、拖动缩放、关联管理和模型列表。原始资料、准确修订及 `docs/design/` 保持完整。

## 发现与修复

- 列表以写事务读取全套正文，并对每个历史版本逐项查询同一修订、实体、制品。改用一致的只读事务、选择身份投影、事务内批量预取；完整版本仍检查清单摘要、准确身份、项目归属、来源及关系/证据权限。权限结果只在同一只读事务复用，写事务与下次请求重新判断。
- 身份验证原本也获取写锁，使只读 GET 仍可能排在后台建库或关联写入后。已有账号与令牌改用只读事务逐次校验；旧实例首次创建账号和迁移凭据才使用写事务。PostgreSQL 初始化顾问锁也只用于真正的创建路径。
- Studio 先请求资料包和迁移状态，历史版本独立读取。更新使用已加载的选择版本直接提交，后端继续检查 `If-Match`；冲突后刷新。轮询等待上一次请求完成，离开页面取消读取，连续提交只执行一次。
- 资料切换批量更新准确选择，跳过未变化项；自动完整备份、人工正文及章节映射仍保留。读取旧成员时批量预取实体和制品，避免逐章查询。
- 早期导入的文档没有 `material_path`，旧实现将这些文档全部写入同一个 `None` 字典键。修复后从准确原始制品路径恢复匹配，人工草稿采用其记录的导入制品；同路径的多个逻辑文档拒绝静默合并。来源正文未变时保留人工正文，移动路径也保留原始来源权限。
- 相同资料重复新增被拒绝；当前包的未变化更新直接复用，跳过解析和建库。并发解析在提交前再次检查。单文件改名仍识别相同内容；不同项目独立判断。大量文档路径重叠的新包返回 `VKS_MATERIAL_UPDATE_REQUIRED`，页面保留文件并提供“改为更新”入口。
- 导入方式必须明确选择新增或更新；切换类型清空旧文件与名称，自动名称跟随新文件，更新时保留目标包名。“新增”用于独立资料包，“更新”沿用已有逻辑包及文档身份。
- 迁移重试按账号、项目、草稿和当前资料组合复用在途任务；后台保存说明导致选择计数变化时，也不会因再次点击而创建重复任务。页面突出一份当前迁移进度，将其余记录折叠为历史，区分排队、建库、关联、取消和旧资料组合。

## 助手与模型交互

- 原文预览在引用跳转卡片之前，先读内容再决定打开哪份文档。
- 图标支持鼠标、触控自由拖动，区分拖动与点击，保存坐标并随视口限制位置。
- 浮动窗口的原生 CSS 缩放替换为四边、四角的自定义手势。整段手势持续捕获指针，并以遮罩阻止下层 iframe 抢走事件；失焦或取消时清理。按动画帧直接更新窗口尺寸，松开后再更新 React 布局及保存偏好，避免鼠标每移动一次就重新渲染正文。提供键盘缩放和恢复默认布局。
- 关联管理采用搜索、状态和模块筛选的紧凑列表，仅在详情区渲染一份完整 Markdown，保留编辑、移除/恢复、准确原文和原型往返。
- 模型列表从服务实际返回的 ID 中默认展示最多六个较新的回答模型，同代日期快照折叠；其余可搜索、展开，每页二十个。当前选择始终保留，不随列表刷新自动更换。真实预览返回 96 个模型，默认显示 5 个，原选择保留。
- 旧 Web 导入页补充网格及草稿选择框的收缩约束；375px 场景同时覆盖长草稿名。

按用户要求，取消平台回答与嵌入模型的每日 Token、每日费用、单次费用拒绝，以及合法实际用量超过旧配置时的拒绝。旧 API 字段兼容并标记弃用，不再执行配额；页面移除对应控制项。用量记账、输入权限、有效响应检查和回答篇幅选项保留，不改变供应商账户或供应商自身限制。

## 删除与恢复

资料包先停用，停用前自动保存完整版本，然后可删除。完整版本可直接删除。删除移入项目回收站，可恢复；资料包恢复后再选择版本启用。当前工作区中正在使用的包不能直接删除，已删除包不能直接更新或启用，已删除完整版本不能直接回退；恢复完整版本时会恢复该版本需要的资料包。

`material_trash` 独立保存项目、对象类型、身份和操作人，迁移 `o48bfd027465`。不修改不可变修订、原始字节、冻结清单及既有引用；删除不是物理磁盘清理。所有列表、删除和恢复仍先验证对象归属及当前权限。

## 测量

同机隔离副本：204 篇文档、5,476 个章节、5,707 个选中修订、8 个完整版本。比较同一实例副本及相同完整来源权限。HTTP 为 ASGI TestClient 的完整请求，各三次；报告中位数，包含 JSON 编码和身份验证，不是跨机器或并发负载保证。

| 读取 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 原完整资料接口（含版本） | 11,416 ms | 449 ms |
| 资料包列表（不等待历史版本） | 与完整接口同步等待 | 46 ms |
| 独立完整版本列表 | 与完整接口同步等待 | 424 ms |

实际运行页初次独立浏览器观察到资料列表请求 74–112 ms。资料整理为 242 篇后，与全量回归并行时三个完整请求为 910、190、189 ms，说明当前数据量、冷读和本机负载会影响该值。首次文档解压、解析、模型生成与首次向量建库不包含在列表数字内。

以下为 cProfile 下的服务阶段计时，含分析器开销，不等同 HTTP 延迟：

| 操作 | 修复前 | 修复后 | SQL 次数 |
| --- | ---: | ---: | ---: |
| 完整资料读取 | 25.19 s | 约 1.36 s | 165,493 → 411（分离列表前样本） |
