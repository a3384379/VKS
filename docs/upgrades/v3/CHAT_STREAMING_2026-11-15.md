# 问答流式输出与助手默认页签 · 2026-11-15

AI 问答由等待完整回答后一次显示，改为模型文字到达后逐步显示。复用当前上下文、检索、提示、输出上限及共享会话操作；没有将完整回答收齐后再做打字动画。

## 行为

- `/interactive/conversation` 按 `Accept: text/event-stream` 返回 `status`、`delta`、`complete` 或 `error`。原 JSON 调用保留兼容，MCP 工具行为不变。
- Responses 和 Chat Completions 使用真实 SSE 增量。页面仅展示结构化回答中 `explanation` 的文字增量，不展示原始 JSON 或推理事件。Markdown 随文字更新，代码图表在完整回答后渲染；用户向上翻阅时停止自动跟随滚动。
- 引用、未知项及最终回答在模型完成并通过 Schema、准确章节和当前资料/权限校验后显示。中途断开或校验失败保留“未完成”标记，不冒充完整回答，也不进入后续追问历史。
- 点击停止会取消本地读取并关闭上游连接；已经显示的文字保留，问题恢复到输入框。已收到的最终用量正常结算；停止或异常时缺少最终用量的调用按原规则保守结算，不把中途占位用量当成最终消耗。
- 修改关联、文档及导出继续使用既有服务、版本及幂等保护。操作期间显示进度状态，仅在服务端实际完成后显示操作回执和下载入口，不流出未保存的计划。
- 原型知识助手每次普通打开默认进入“相关文档”；选择新控件也使用该默认页签。主动选择讲解/问答入口仍进入对应页签，独立文档提问入口仍打开问答。没有修改后台自动关联开关。

模型响应大小、受控连接、外发策略和 8000 输出上限保留。兼容服务若忽略 `stream` 而返回 JSON，只能在其完整响应到达后显示；不自动重发模型 POST。协议参考 [OpenAI 流式响应](https://developers.openai.com/api/docs/guides/streaming-responses)及 [Chat 流式事件与用量](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。
