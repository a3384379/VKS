## 性能证据与验证方法

- 同一临时向量库关闭 GC、执行 100 次读取：旧连接上下文使文件描述符增加 **201**，修复后增加 **0**。关闭 GC 用于比较显式关闭与延迟回收，不据此推算正常 GC 下的长期增长。
- 8 个并发相同语料的冷索引请求：索引构造 **8 次 → 1 次**；另一个语料可在第一个构建阻塞时完成，不以全局串行换取构建合并。
- 合成 SQLite 保持无关写事务未提交期间，目录、正文和关联读取可以完成；原实现会等待写锁。引用检查覆盖孤立章节及部分/全部取消选择。
- 浏览器实际复现 65 篇预取挤出当前正文、上下文 pending 复活、搜索及模型目录晚到、设置保存竞争、360px 输入布局、无 EOF/超大响应、响应式图片解码与 SVG 片段。
- 本机真实 204 篇/5,476 章节的标准正文预热读取约 10 ms；目录、原样定位和关联仍需完整权限/版本核对。本轮未证明这些接口整体时延下降，具体前后 HTTP 数据、完整检查与增量回归结果见 [验证记录](VERIFICATION.md)。检索只调用本地相关章节入口，不为性能采样调用付费模型。

量化脚本、完整输出和私有资料验收位于忽略目录 `.vks/studio-preview/checks/max-audit-20261114/`。可提交的回归均使用合成资料；审计过程中发现的原始失败与最终结果分开保留。

## 复审和边界

第一轮按前端交互、AI/RAG、资料/Runtime/导出及后端读取分工复现并修复。第二轮交叉复审和性能复测追加确认 A04、A18、A15、A29、A30 以及 A27 的 finally 竞态，分别补回归。未将曾怀疑但核对现有项目 key 后排除的设置跨项目 ref 问题列为发现。

- PostgreSQL 的行锁结算已修复，但没有配置真实 PostgreSQL 并发专项；SQLite 测试不能证明 PostgreSQL 多进程验收通过。
- 未重复真实收费业务、Safari/Edge、全部第三方模型服务及正式 HTTPS 部署验收；外部服务延迟仍影响模型生成时间。
- Runtime token 过期或因容量淘汰后需工作台重新登记；这不清除原生页面的持久存储。
- 任意静态站的相对 ESM、CSS @import 和动态远程依赖不在本轮普遍兼容承诺内。
- 修复后的单文件阅读器用于之后生成的成品。此前已经下载的 HTML 是固定快照，需要重新导出才能获得阅读器修复。
