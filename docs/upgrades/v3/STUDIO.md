# VKS 3.0 Studio 首个交互闭环

2026-11-11 · 对应 [D2 方案](VKS_3.0_交互工作台重构开发方案.md) 的 P0 及部分 P1。当前入口为新建的 `apps/studio`；浏览器原始资料运行页位于 `apps/runtime`。

## 现在可以体验

- 文档目录按导入资料保留：顶部分类，左侧按来源顺序展示文件夹、文章及可展开小节。HTML 手册优先采用其声明目录；普通文档 ZIP 使用自身路径和归档顺序。多资料包各自保留目录，搜索、引用和跨文章链接会自动切换到对应分类与小节；目录随准确资料版本保存及恢复。
- 文档正文、小窗和 AI 讲解统一支持中文加粗、表格、嵌套列表、脚注、公式、代码高亮及本地 Mermaid 图表；原文不重写，原手册仍可独立阅读。完整说明见[文档格式](../../MARKDOWN_FORMATS.md)。
- 在「原型与文档」导出当前成品库，或在完整版本旁导出指定版本。下载单文件 HTML 后可离线阅读、搜索和定位原型，联网时由使用者自行填写 Key 问答；详见[单文件成品库说明](READONLY_LIBRARY.md)。
- 模块与控件自动伴读：先显示相关原文，RAG 向量与关键词合并检索，AI 在后台核对关联及讲解。嵌入模型与建库进度在“AI 设置 → RAG 向量知识库”维护。
- 在 Studio 中操作原 HTML 的菜单、业务页、表单、页签和弹窗。知识小窗的开合保留原型实例与已输入内容。
- 右下角“知识助手”默认收起，点击图标展开；后台找到文档后以角标提示，不主动弹出面板。
- 普通点击原控件时，后台整理相关知识；已展开的助手跟随显示。可以窗内预览原文、打开全文或查看 AI 讲解。
- 助手“选项”集中提供模块知识、自动关联、固定当前知识、展开方式、模型设置与关联管理。需要补充时，选择“手动补充关联”再点击原型控件，填写说明、选择准确章节并保存。
- 独立文档阅读器提供 204 篇资料的标题搜索、目录、完整章节和关联操作入口。从章节可跳回页面及控件；有已记录打开步骤的弹窗可自动重开。
- “原手册”使用另一运行实例打开用户提供的原始手册，保留其自身目录、搜索和原有展示。当前关联维护位于工作区文档阅读器。
- 在关联管理中打开原型、查看原文、编辑说明、移除或恢复关联。保存进入数据库；浏览器刷新及重新登录后仍能读取。

## 启动

先安装锁定依赖：

```sh
uv sync --frozen
npm ci
```

已有导入实例可通过 `VKS_DATA_DIR` 指定数据目录。首次准备云收费试点时，使用用户选定的两份资料：

```sh
PYTHONPATH="$PWD/services/api:$PWD" uv run python scripts/prepare_studio.py \
  --data .vks/studio-preview/data \
  --prototype '/所选目录/云收费页面原型合集(1).html' \
  --handbook '/所选目录/云收费系统项目知识手册(1).html'
npm run dev:studio
```

Studio 默认为 `http://127.0.0.1:5193`，API 使用 8014，Runtime 使用 5195。启动脚本检查端口，支持 `VKS_STUDIO_PORT`、`VKS_API_PORT`、`VKS_RUNTIME_PORT` 和 `VKS_DATA_DIR`。资料准备脚本拒绝覆盖已有数据库，并在数据目录旁保存 `preview.json`，记录项目和草稿身份。

本地首次创建实例的管理员为 `owner / owner`。打开项目后选择“原型”；新实例尚未创建关联时，可以直接在 UI 中开始维护。导入生成的原始资料、数据库和试用记录位于忽略目录。

## 实现与数据

`InteractiveKnowledgeService` 复用原有草稿权限、不可变修订、业务点、准确章节、出处继承和保存事务。新 HTTP 契约位于 `/api/v3/projects/{pid}/interactive`，提供目录、包内容、准确文档、关联读取、保存、移除与恢复；使用当前草稿选择版本和对象版本控制并发，关联保存支持幂等重放。

P0 使用不可变原始 `Artifact` 的 ID 和 SHA-256 固定运行包；DOM 定位存入 `Action` 的不可变修订 `interactive_anchor` 元数据，说明与出处沿用 `has_business_point` 和 `supported_by_section`。定位包含包身份、业务页路径、嵌套 frame、状态容器、选择器、标签和打开步骤。每次定位要求唯一可见目标及相同标签，失败时提示用户打开状态或重选。首次试点中的三条关联为人工维护说明，原型点击不改变其证据类别或因果依据。

Studio 从 API 读取获授权原始字节，核对摘要后通过专用 MessageChannel 转移到独立 `*.localhost` 运行实例。原型与手册具有不同来源。API 凭据保留在 Studio；Runtime 仅服务固定的公开启动文件，不能读取数据目录。HTTP CSP 禁止运行材料联网和表单外发；原 HTML 的内部 Blob 资源及原交互保留。导入、索引与后端任务继续只处理数据。

## 验证方式

`make check` 包含新增 Studio 的 TypeScript 和生产构建。`tests/interactive` 使用可提交的合成资料覆盖实际浏览器闭环、持久化、双向导航、读取隔离、幂等、并发冲突、跨项目引用、准确章节、冻结版、原包授权闭包、移除及恢复。契约通过 `make contracts` 更新，并运行原有官方 MCP HTTP 与 stdio SDK 回归。

用户提供资料的本地浏览器验证另行记录，不将这些原始文件纳入测试仓库。其结果见 [验证记录](VERIFICATION.md)。

## 手册式 AI 连接设置

Studio 顶部“AI 设置”按原手册的交互重做：选择服务商和回答模型、查询当前 Key 可见模型、选择回答长度、测试所选模型，最后统一“保存并使用”。

- 服务商预设包含 OpenAI、DeepSeek、阿里云百炼和自定义兼容接口。预设自动填写地址、协议与模型；具体账户权限以服务返回和测试结果为准。
- 模型使用可搜索的下拉框。可获取账户模型、保留当前选择，或手动填写服务提供的精确模型 ID。百炼的工作区域名使用其原生目录接口；其他兼容服务使用 `/models`。
- “我的连接”保存多个连接与模型选择。切换连接恢复原配置；不同连接按准确端点保存独立凭据。原有 OpenAI Key 继续保留，不向其他服务商自动转发。
- 回答长度提供 1,500、2,500、4,000、8,000 token 预设。更多设置内维护每日预算及内容发送范围。
- “测试连接”只发送固定的测试消息，会产生少量模型用量，不发送项目文档。它校验基础文本生成，结构化输出等能力仍需功能任务验证。
- 地址、协议、连接名称和预算按需展开。Key 在本机后端保存，返回值和审计不含密钥。保存新连接时，本机管理员可在页面登记 HTTPS 服务地址，仍沿用固定 IP、重定向及保留地址限制。

连接的非秘密设置存入新增的 `model_connection` 表；当前项目模型策略引用所选连接。凭据在实例的 `model-credentials.json` 中以不可变引用保存，文件为 0600。SQLite 自动新增表；PostgreSQL 使用 Alembic 迁移 `m26fdb805243`。

实现参考用户手册中的模型下拉、账户模型查询和模型测试，并核对 [OpenAI 模型目录](https://developers.openai.com/api/docs/models)、[OpenAI 模型查询](https://developers.openai.com/api/reference/resources/models/methods/list)、[DeepSeek 接口](https://api-docs.deepseek.com/api/list-models/) 及 [百炼兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[百炼模型目录](https://help.aliyun.com/zh/model-studio/list-models)。预设不表示已对每一家服务完成真实验收。

## AI 自动关联、模块知识和悬浮助手

小窗提供“相关文档 / AI 讲解”两个页签，分别阅读原文与模型解释。Studio 同时维护模块和控件两层知识：进入模块或普通操作时，后台检索相应知识。助手默认收起；自动检索与生成不会重新展开已收起的面板，图标以角标和处理中圆点提示。点击图标才展开内容，收起或切换助手选项保留原型表单和弹窗状态。

常驻工具栏已移除。助手右上角“选项”集中提供“模块知识”、自动关联、固定当前知识、浮动/侧边展开、模型与知识库设置、关联管理及可选手动补充。自动关联开关在本浏览器保存偏好，关闭后不再安排进入页面和普通点击触发的自动模型请求；已开始的请求可继续完成。固定当前知识时暂停跟随普通操作。

| 入口 | 行为 |
| --- | --- |
| 右下角助手图标 | 展开当前知识，或收起面板 |
| 进入模块 / 助手选项内“模块知识” | 检索模块职责、业务范围和主要流程；自动检索在后台进行，主动选择时展开原文 |
| 右键控件 | 查看关联文档、AI 讲解、重新检索，以及可选手动补充 |
| 右键页面空白处 | 对当前模块执行相同操作 |
| `Shift + 右键` | 保留浏览器原生菜单 |

根据用户反馈，移除原先的 `Alt/Option + D`、`Alt/Option + A` 和 `Alt + 单击` 自定义入口。菜单仍支持方向键、Home/End、Enter 和 Esc；助手内 Esc 返回内容或收起面板，焦点回到图标。普通单击保留原型逻辑。模块以同一原包、页面、frame 的 `body` 目标独立保存，按钮以准确 DOM 目标保存，两者不会覆盖。模块和控件都可从原文章节返回。

2026-11-12 起采用真实 RAG 混合检索：中文二元词和英文词的 BM25 索引先返回匹配章节，独立的语义检索再合并章节向量结果；两步均先限定当前项目、准确修订及当前权限。小窗直接显示可点击原文，不等待 LLM。自动关联判断与讲解在后台继续进行，不阻塞页签和文档导航。不同控件/模块的模型调用不再共用一把覆盖整个网络请求的锁；同一目标仍合并重复请求。已有模型知识可以复用数据库中的讲解。

“AI 设置”底部提供 **RAG 向量知识库**：选择嵌入连接、嵌入模型、维度和独立的每日 Token 预算，测试连接、建立/增量更新索引并查看进度。嵌入连接可以独立于回答模型；当前预设为 `text-embedding-3-small`、512 维，也支持下拉选择大嵌入模型和相应维度。建库会向所选嵌入服务发送获授权的文档片段，计入独立嵌入用量，不占用回答模型的 Token 预算。

本地 `rag-vectors.sqlite` 保存真实的归一化 float32 向量、准确章节身份、片段和查询向量。900 字符片段保留 120 字符重叠；模型、端点、维度及切分版本构成索引命名空间。查询先按当前可读且选定的章节过滤，再以精确余弦相似度检索，与关键词结果作排名融合。当前个人资料规模使用 SQLite + Python 的 C 实现 `math.sumprod`，不依赖额外向量数据库服务。向量是可重建缓存，知识主库中的原始字节、修订与关联仍是事实来源。

建库按批次保留进度，失败或重启后可继续；修改文档只为新修订建立缺失向量。当前建库任务运行在单个 API 实例的后台线程中，尚未作为分布式建库队列验收。首次建库会预热模块查询，同时为逻辑路由与原 HTML 物理路径保存同一查询向量，控件查询向量也可缓存。索引不会在切换页面时重新生成。当前缓存文件位于实例私有数据目录，不进入 Git/镜像；现有实例备份流程不包含该可重建缓存，恢复后可重新建库。

检索与模型生成是不同延时：当前已有章节通常可在秒级先显示，新的完整讲解仍受所选模型与网络影响。当前讲解沿用完整结构化响应，尚未实现手册式逐 token 流式讲解；不能把首批文档时间当成 LLM 完整回答时间。API 参数与维度依据 [OpenAI Embeddings 文档](https://developers.openai.com/api/docs/guides/embeddings) 及 [创建嵌入接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create)。

项目 AI 设置中的“允许 AI 使用本项目获授权的相关内容”授权本功能使用当前选定的离线原型上下文及可读文档。原始材料导入的出口默认值不被改写，通用证据网关的策略保持独立。禁止发送机密资料，源码派生内容仍受项目 `allow_source` 与来源权限约束。

模型必须返回结构化讲解及候选集合中的准确章节引用；不存在的引用、过期基线、资料或模型策略变化会拒绝保存。关联置信度至少 0.7、有章节依据且草稿可编辑时，自动创建不可变知识修订，标为模型推断、保留全部实际发送章节的出处权限。现有人工说明不会被覆盖，已移除的关联不会自动恢复。只读版本可讲解而不写入。首次模型讲解取决于网络与模型，已有关联原文可直接查看；材料不足会列出缺口。

HTTP 入口 `/api/v3/projects/{pid}/interactive/related` 提供无需模型生成的章节匹配，`/semantic` 提供 RAG 混合结果，`/assist` 负责模型判断及讲解；`/rag/settings|status|test|build` 管理向量配置、进度与增量构建。共享服务重验项目权限、准确输入和模型设置，不向 Runtime 提供凭据。自动写入持锁后再次核对实际输入；其他后台关联仅改变草稿计数、未改变输入时，不会使无关模块的生成失败。人工关联不会被临时讲解覆盖，未写入的讲解不会标为“已保存的准确引用”。

## 多项目、可插拔资料包与完整版本 · 2026-11-12

顶部文件夹图标进入“项目中心”，可创建、搜索、编辑、归档和打开项目。每个项目独立保存原型、文档、模型策略、RAG 范围和关联。助手自动关联偏好按项目保存于本浏览器。既有云收费实例在第一次打开时登记为资料包，保留原始字节和既有知识身份。

“资料管理”提供以下操作：

1. 选择“交互原型”或“知识文档”，新增资料包或更新指定包。原型接受单 HTML、云收费离线 HTML 和静态站 ZIP；文档接受 Markdown、文本、普通 HTML、云收费手册及文档 ZIP。
2. 上传后“解析并预览”。新包版本先独立保存，当前工作区继续使用原版本。可以连续准备原型与文档，然后一次启用；“整套替换”会停用未列入本次组合的资料。
3. 已安装资料可选择版本、启用或停用，并设置当前原型。多个原型可在原型页切换，多个原始文档包可在文档页选择。仅替换文档保留已有原型实例及输入；更换原型或恢复完整版本重新创建对应实例。
4. 更新前自动保存完整版本，也可以填写版本名称主动保存。保存复制并冻结准确基线，当前工作区保持可编辑。恢复时先保存当前组合，再从所选版本创建新工作区；刷新及重新进入项目继续使用恢复后的工作区。
5. 更新后后台执行 AI 关联迁移。界面显示逐项结果、失败原因和暂未定位的位置；模型未配置、预算不足或依据不足时保留待关联状态，可配置后重试，不要求逐条人工绑定。

资料包使用稳定的 `page` 逻辑实体和不可变修订，`material_package` 元数据记录准确成员、运行入口、格式、资源及静态定位目录。原始上传对象与浏览器查看派生对象分别保存。文档和章节沿用原有准确修订；人工编辑后未变化的上传文档保留当前正文。停用包移除其当前文档及章节选择，历史仍可读取；停用前的人工编辑保存为可重新启用的包修订。

同一包更新按稳定 ID / 属性、页面及状态范围检查位置。只有唯一匹配才沿用动作身份；无法确定时列为待定位，新控件正常操作时可重新自动关联。变更引用由模型重新检索核对；人工说明不被改写，AI 可以迁移其章节引用，模型说明重新生成。用户移除的关联不会恢复。后台任务有持久化进度、来源授权和资料组合校验，回退或再次替换后不接收旧迁移结果。

检索仍先限定项目、当前准确章节和权限，停用的文档不参与当前关键词或向量结果。已配置嵌入模型时，启用新文档会安排增量建库；原文检索可以先使用，模型判断与讲解在后台继续。向量缓存不作为知识快照的事实来源。
