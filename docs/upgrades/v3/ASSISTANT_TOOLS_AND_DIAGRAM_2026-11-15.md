# 助手重新关联、会话工具及原样图表修复

2026-11-15 后续已拆分重新关联与独立讲解。下文保留早期交付记录，当前页签入口、提示词和保存行为以[分离补修记录](ASSOCIATION_EXPLANATION_SEPARATION_2026-11-15.md)为准。

本轮按用户追加要求修改 3.0 Studio。继承[性能优化](ASSOCIATION_PERFORMANCE_2026-11-15.md)的已有结果、任务检查点及默认单目标推理链路；不重置扫描、不重新跑整批关联，也不改动原始资料或 `docs/design/`。

## 使用方式

- 原型控件或模块的知识助手 →「相关文档」或「AI 讲解」→「AI 重新关联」。展开后可填写提示词，例如“重点说明退款的前提、结果和注意事项”，点击「按提示重新关联」。提示词最多 4,000 字，可留空重新生成。依据不足或置信度低于 0.7 时不覆盖已有结果。
- 「AI 问答」可以直接发送“请修改关联文案，重点说明办理前提”“请修改当前文档，只润色第一章节，保留其他章节”“请导出当前文档为 PDF”“请导出项目文档为 Markdown”等明确操作要求。普通问题继续走原问答流程；询问如何操作、解释材料中指令或明确要求不操作时不会调用写工具。一次消息执行一类操作，修改和导出分条发送。
- 文档修改完成后显示结果按钮，并刷新当前文档。操作结果保留在对话中；之前的普通问答不再作为新版本的事实依据。外部资料替换仍清空旧范围的问答。导出任务在回答中显示状态、错误或下载入口；下载继续校验当前权限。
- 关联管理 → 编辑关联：右上角 X、取消、Esc 都关闭整个编辑窗口，放弃未保存输入；重新打开读取已保存内容。保存提交期间禁用关闭，防止丢失保存结果。

整项目导出支持已有 Markdown、PDF、单文件 HTML、可回导 VKS 包。指定文档导出支持 Markdown、PDF、单文件 HTML；使用独立快照，仅包含指定文档和章节，Markdown 不附带可能包含其他文档的原文件。可回导包沿用整项目范围。单文件 HTML 沿用当前真实嵌入建库要求，配置不足或建库失败会显示任务错误，不声称已完成。

## 共享 HTTP / MCP 实现

会话和 MCP 直接复用 `InteractiveKnowledgeService`、`DocumentService`、`MaterialService` 及导出任务服务，不绕过现有权限或版本检查。新增工具使目录从 25 个增至 30 个：

| MCP 工具 | 用途与并发条件 |
| --- | --- |
| `get_interactive_context` | 读取准确草稿/保存版本、当前控件关联、可见文档和章节候选 |
| `save_interactive_binding` | 保存关联标题、文案及引用；修改需准确 binding ID、binding version、point revision 和 selection version |
| `get_workspace_document` | 按版本读取完整 Markdown、章节和 row version |
| `save_workspace_document` | 按 base revision / row version 保存文档新修订，保留章节锁 |
| `export_workspace_documents` | 复制导出快照并创建任务；可传 document IDs；用已有 `get_job` 查看及取得下载地址 |

Studio 新增 `/interactive/reassociate` 和 `/interactive/conversation`。MCP 适配器的读取/文档保存/导出映射至 `/interactive/tools/*`，关联保存复用原 `/interactive/bindings`。HTTP 和 MCP 定义由实际模型重新冻结；导入资料和对话历史均是数据，不提供脚本或任意网络工具。

重新关联将本次提示词纳入检索和生成身份，仅对用户主动操作允许改写已有人工文案。生成前后、最终保存事务内核对目标关联和全部输入；人工修改、移除、冻结、权限或模型策略变化时拒绝旧结果。普通自动关联的人工内容保护保持原有行为。

文档会话修改使用结构化章节替换计划，准确章节 ID 枚举、输出完成状态、用量和大小均校验；未修改章节按原文拼接。完整文档超出当前模型输入额度时明确返回错误，不截断后冒充全文修改。计划先持久化，再以幂等键在同一保存事务内应用；重试不再生成不同文案。人工锁、原始字节、旧修订和来源权限继承保留。写入结果与导出状态由服务端生成，模型不能自行宣称保存或构造下载地址。

## 原样手册图表重影

此前 `classic` 和图片缩放修复验证的是标准 Markdown 渲染器，未覆盖用户照片中的原样 HTML 图表弹窗。本轮在用户真实图 550 复现了另一条链路：

`ResizeObserver` 自动适配 → SVG 尺寸变化 → 自动滚动条出现/消失 → 可用宽高变化 → 再次适配。

启用经典 17px 滚动条、1.25 DPR 并测试临界窗口后，45 帧中最多发生 43 次切换，SVG 宽度在 1,397 / 1,414px 间振荡；无需滚轮输入也会持续。默认无头 Chromium 隐藏滚动条，会掩盖该问题。

修复在原生弹窗 `#diagram-dialog #diagram-viewport` 预留双轴滚动条空间（`overflow: scroll; scrollbar-gutter: stable`）。Runtime 文档桥接、独立空白模板及新导出的原样阅读器同步。原 SVG、缩放和平移事件保留，未使用位图替换。已有导出文件保持不可变，重新导出包含修复；已打开的工作台需刷新后重新打开图表。

真实 Studio 图 550 的 10 个临界窗口高度 × 两种适配方式共 20 例，修复后所有采样均为 0 次尺寸切换。新增回归使用真实原生查看器代码、经典滚动条、两种 DPR 及文档自替换，覆盖滚轮、拖动、关闭重开、原 SVG 不变；同一测试在旧桥接上稳定失败，在新桥接上 2 项通过。相关原生文档、导出和独立手册另有 10 项专项通过。

## 真实资料与质量边界

使用当前云收费项目的隔离数据库副本及现有模型连接，保持输出上限 8,000：

| 操作 | 实测结果 |
| --- | --- |
| 提示词重新关联“新增收费项” | 11.393 秒，保存成功，3 个准确章节引用；旧关联修订保留 |
| 会话润色一份实际办理流程文档的首章 | 7.618 秒，保存成功；日期、业务范围及限定条件保持，其他 6 章原文保留 |
| 原请求幂等重试 | 返回同一文档修订，无再次模型改写 |
| 会话导出当前文档为 PDF | 2.047 秒创建任务，任务成功，实际文件可读取 |

人工对照了上述实际生成文案与引用，文档修改仅润色请求章节。该样本验证功能闭环，不代表所有业务内容、提示词及供应商的质量验收。实测不写入用户正在使用的主库；凭据、原文及私有验收记录留在忽略目录。
