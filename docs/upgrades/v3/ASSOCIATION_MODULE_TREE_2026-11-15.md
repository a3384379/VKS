# 关联查询的模块树 · 2026-11-15

用户反馈关联查询中的模块下拉框将所有页面平铺，没有体现前端模块与子功能的层级。本轮将该筛选改成可展开、收起和搜索的树。

## 行为

- 从当前可读原型关联的实际路由目录组织模块层级，例如「物业缴费 → 收费项目管理」「物业报表 → 应收统计」「物业催缴 → 催缴策略」。已知离线适配器的 `/actual/` 前缀不作为业务模块显示，目录有多级时保留中间层级。
- 选择父模块筛选其全部子功能关联；选择功能页筛选该页的模块说明、控件及内嵌页面控件。控件留在结果表中，不平铺成模块选项。筛选按钮与结果行显示完整路径。
- 支持模块/功能搜索，搜索结果保留祖先路径；支持键盘方向键、Enter、Home/End、Esc、点击外部关闭和窄屏布局。状态、正文搜索和分页继续与模块范围组合使用。
- 使用源页面名称，缺少已保存模块说明时按需读取已有的只读页面清单补齐名称。没有源标题时保留路由名；无目录的旧页面归入包名称或「其他页面」，不删除旧关联或猜测其业务归属。同名但不同资料包的模块保持独立，并标明资料包。

## 实现边界

`bindingModuleTree.ts` 只从已经过滤权限的关联创建树节点，页面清单仅补充名称，不增加未关联或不可读页面。功能页身份使用准确资料包和路由；过滤使用关联 ID 集合，父级包含后代，其他项目和资料包不会因同名而合并。

`BindingsManager` 复用当前目录数据，首次展开筛选才请求已有 `/associations/inventory`；不阻塞初始列表，不下载原型运行包，不发起模型、扫描或写请求。项目、版本和资料变化清理或更新对应范围。没有新增 HTTP / MCP 契约或数据库迁移。

## 验证

新增 6 项前端范围测试，覆盖父子范围、内嵌控件、名称补齐、不可见清单不生成节点、同名包隔离、多层目录及稳定选择身份。关联管理浏览器 4 项通过，覆盖真实展开收起、父模块/功能页选择、状态组合、搜索保留父级、键盘、手机宽度及原编辑/移除/恢复/分页；控制台无异常。

以真实云收费项目的数据库副本和独立浏览器验证：全部 **1,409 条**，选择「物业缴费」为 **1,007 条**，选择「收费项目管理」为 **20 条**；逐行核对均属于所选功能路径。顶层为物业缴费、物业报表、物业催缴，旧的未分类页面保留在「其他页面」。测试未向用户主库保存测试内容。
