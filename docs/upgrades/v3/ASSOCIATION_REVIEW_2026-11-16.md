2026-11-17 文档章节反向关联：章节旁的“关联操作”先打开可搜索、分页的目标模块选择器，使用当前草稿实际清单返回的准确资料包、模块定位和绑定基线。选择后进入既有 AI 关联预览，将当前章节与原关联说明、旧依据一并送入模型补全说明。输入方向仍可留空；生成后默认新旧对比，确认才一次保存新说明及章节关联，取消不写入。此入口不打开或复用上次原型的问答助手。已保存版本只读，已移除模块不参与选择。

`ReassociationInput.additional_section_revision_ids` 为可选准确章节 ID 列表（最多 12 章）。服务检查章节处于当前可读且模型允许的资料范围，恢复完整原文，作为预算内不得丢弃的输入，提示模型融合新增依据并保留对应引用。模型漏掉新增引用时拒绝可保存结果；无法装入完整章节时返回容量错误。该列表参与请求指纹、上一版预览与批次身份检查，确认继续校验权限、资料和绑定版本。`GET .../reassociate/targets` 增加 `q` 名称/路径过滤，计数与分页发生在权限过滤及搜索之后。无数据库迁移，原章节及绑定历史不覆盖。

交互工作台的 AI 重新关联改为先生成候选，再由用户确认替换。此前记录中 HTTP `/interactive/reassociate` 直接保存的行为由本记录替代；既有应用服务、MCP 显式写工具及自动补齐后台任务保留原契约。没有新增审批状态或数据库表。

## 用户流程

- 原型知识助手只在原型和文档页展示；资料管理、关联管理和 AI 设置不显示通用助手。切回阅读页保留问答草稿。关联管理自己的编辑器和预览弹窗继续可用。
- 打开已保存的模块或控件关联只读取现有结果。绑定列表尚未加载完成时不启动自动生成；服务返回准确绑定时也不误触发模型。自动补齐仍可处理真正未关联的目标。
- 助手底部的 AI 关联入口替代重复的 AI 讲解按钮；讲解使用中间页签。关联入口先打开提示词输入，不直接发送模型请求。
- 单项：输入方向 → 生成 Markdown 预览 → 确认替换并保存。关闭、取消或失败不替换现有绑定。确认保存同一份预览，无第二次模型调用。
- 批量：可选择若干目标，或按范围补齐未关联/重新关联全部。默认范围仅含模块，用户可包含控件。共同提示词生成后显示分页列表，选中一项才加载该项完整内容；可单独修改方向重新生成或从本次移除。移除只改变待保存名单，不删除或排除原绑定。整批保存对名单中的预览执行一次原子提交，任一冲突则全批不替换，列表保留以供处理。
- 单项和批量都不静默保存依据不足或失败结果；批量需重试成功或移除这些项后才可保存。
- 批量结果可按模块、页面、控件或路由关键词搜索，并按状态筛选整个批次。「查看需处理」可跳到生成失败、依据不足和其他未就绪项。重新生成状态按条目记录，可以切换到其他条目继续重试。保存统一检查本次保留的所有预览，范围与当前列表筛选无关。
- 回答依据保留文档与章节小卡片，不在回答下展开原文正文；卡片和数字引用仍可打开完整 Markdown 原文。
- 列表、详情与预览弹窗采用响应式稳定外框及内部滚动，避免长短内容切换推动页面布局。

## HTTP 与持久化

`POST /api/v3/projects/{pid}/interactive/reassociate` 返回 `saved:false`；符合依据要求时返回不可变 `preview_id` 和 `can_confirm:true`。`GET .../reassociate/previews/{preview_id}` 读取同一结果；`POST .../reassociate/confirm` 接收 `{preview_id}`，只确认已生成内容。

批量入口 `POST .../reassociate/batch-preview` 接收草稿、提示词、`missing/all` 范围、可选准确目标列表及是否仅模块，返回持久任务 ID。`GET .../batch-preview/{jid}` 分页返回目标元数据、状态与候选 ID，不读取候选全文；完整内容沿用单项预览端点。单项重生成沿用 `/reassociate`，带服务器返回的准确请求、批次和条目 ID。`POST .../reassociate/batch-confirm` 接收任务 ID 及剩余候选 ID，事务内整批保存。

`POST .../batch-preview/{jid}/results` 是只读查询，接收关键词、状态、分页和当前窗口的临时移除及依据不足项。权限检查先于筛选和计数，服务保留整个批次的进度以及筛选后的分页总量。现有 GET 分页保留兼容。

`GET .../reassociate/targets` 从现有原型目录和当前绑定生成准确目标元数据，支持 `module_only`、`mode=missing/all`、`offset/limit`。前端不会根据标题猜测目标选择器或身份。

候选使用现有不可变 Artifact 对象保存，记录原始目标、绑定版本、生成请求指纹、实际发送给模型的全部修订来源、发起人和可选批次条目。生成阶段不写入业务点修订、关联选择或发布版本。任务记录只保存候选引用和进度；崩溃发生在候选提交后、进度提交前时，恢复会复用已经提交的候选。

确认事务重新检查当前权限、草稿状态、准确目标与绑定基线、输入与模型配置指纹及排除状态。来源权限变化后不能通过列表名称、计数、预览或确认读出受限候选。确认幂等重放不重复新增修订，也不能覆盖确认后发生的人工修改。

批量预览通过现有持久任务分发，使用相同模型请求容量预算；不阻塞普通任务分发。取消、授权撤回、输入变化、attempt 或租约失效会阻止候选提交；已发送请求可能仍由供应商计费，但不会替换原关联。
