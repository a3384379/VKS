# 扫描与关联独立推进及结果分页

2026-11-15，开发基线 `f36b838`。本轮延续预关联方案，修复用户反馈的部分扫描无法继续、关联占用分析入口、并行设置不一致及分页内部仍有滚动条。原始 `docs/design/` 保持不变。

## 行为与兼容

- 共用一个 N（1–4）设置。扫描 Runtime 为 N 路，AI 关联执行为 N 路，阶段同时进行时最多 2N 路；这是任务并发，不承诺模型供应商或浏览器 CPU 等比例提速。暂停/停止后继续与重试使用当前选择，活动请求退出前拒绝改动；旧客户端未传新值时沿用原设置。只更新调度配置，目标与操作组快照保持不变，并记录前后路数。
- 分析按钮不再被关联任务占用。已有部分扫描可继续，仅保留成功页；单独扫描不额外启动关联，已启用的流水线继续逐页提交关联。暂停扫描不取消正在运行的关联。
- 旧的“仅关联已采集内容”批次曾把 `batch_job_id` 作为禁止续扫条件。移除此耦合；显式升级时，按账号、项目、准确资料组合及目标身份采纳原任务的目标标记，保留不可变任务输入，只为新增页面生成任务。同一轮旧批次占用的 AI 路数计入限制，避免升级后叠加调用。
- 已运行旧批次的逐项检查点可提前同步进聚合状态，不等待整个批次结束。本地 Dispatcher 可能仍阻塞于旧批次的模型调用，因此汇总还会薄投影读取原任务的实际计数，立即反映原进度；不将数千目标都显示为同时执行。界面合并原批次与续扫汇总，停止原关联使用独立状态，不被扫描的忙碌标记阻断。
- 进程恢复保留当前处理轮次的检查点，包括依据不足；用户显式重试建立新的处理轮次，仍重试先前未成功项，即使再次中断也不丢失其重试意图。成功保存、人工与用户排除结果继续保留。未保存的在途调用不属于已完成检查点，不能声称模型调用恰好一次。
- 扫描启动可以携带准确资料组合摘要，避免自身后台关联只增加草稿计数时误报版本冲突；真实文档/原型替换、冻结、撤权及客户端接管仍拒绝旧范围。旧客户端未传摘要时保留严格版本校验。
- 逐项结果每页 10 条，取消内部限高和滚动条。普通结果本地切片，超过摘要上限的任务由服务端按 offset/limit 分页；不再“加载更多”累加全部 DOM。每个任务的页码独立，轮询不重置页码，关闭、切页和卸载取消旧读取，错误可原地重试。长说明默认缩短并提供完整展开；移动端改为单列。
- 主关联列表默认每页 10 条，可选 20/50 条，前后页与首页/末页切换。筛选变更重置页码，后台刷新不重置；只有可读结果真正缩短时才收敛越界页码。数据刷新期间的临时空列表不清空分页状态，详情始终对应当前页。
- 固定构建预览启动时复制独立静态资源快照，后续验证重建 `dist` 不会让运行中的旧 API 暴露新前端。

## 验证与边界

合成回归覆盖旧关联运行时续扫、只扫描不产生新 AI、旧目标不重复提交、暂停互不取消、资料摘要与真实版本冲突、1/4 路数据库领取和本地执行，以及恢复时不重发已处理的依据不足目标。独立 Chromium 验证按钮和实际页面采集/队列行为；模型使用替身，未据此声称真实收费业务已验收。

最终全量检查与本机预览升级结果记录在 [验证记录](VERIFICATION.md)。没有新增数据表或更改模型供应商协议；契约新增可选的准确资料组合字段。私有预览数据、备份、模型配置及凭据不进入 Git。
